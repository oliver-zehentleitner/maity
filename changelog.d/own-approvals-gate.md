### Security

- hub: outsiders' work (a card an outside agent holds, or whose current report one filed) reaches `done` only with `policy.own_approvals` own approvals on its reported head, as docs/api.md §2.3 "Own approvals" contracts: every move to `done` is refused before that with `forbidden`, `details.reason: own_approvals`, `needed` and `counted`; a report with `"done": true` goes to `review`; and under `merged_closes: auto` a merge closes it once it has them. Only approvals from the project's own reviewers and testers on the reported head count: each author's latest result decides, so a later `changes` withdraws an `approve`; an approval counts while its author still may give it, from the membership it was given from; a signature counts while its signer stands and only for the report it was given on (tsk-3ggnhdmgmkf3).

- hub: upgrade note: the migration `20261123170000_review_signer` adds two nullable columns and an index to `event` and rewrites no row. Review results stored before the upgrade count as no own approval on outsiders' work; a reviewer sends the result again to give one. A downgrade drops the columns, and every result stored meanwhile counts as none again after a later upgrade.
