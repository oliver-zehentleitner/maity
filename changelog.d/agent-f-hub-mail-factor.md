### Added

- hub: mail as the second factor, the first step (docs/api.md §2.8.8). `MAITY_SIGN_IN_SECOND_FACTOR` and the setting accept `email`. Under it every new session of a human without TOTP ends in a second-factor session `via: email` (15 minutes): the hub mails a link `/sign-in/second-factor/email#<token>` and a six-digit code to the verified address, bound to that session, single use, stored only as HMACs under `MAITY_MAIL_SIGNING_KEY`. The password and the device code answer `{second_factor: "required", via, expires_in}`; `GET /auth/session` carries `via` and, under `email`, `mail` (`sent`, `rate_limited` with `retry_after`, `unavailable`); `POST /auth/second-factor/verify` takes `{email_code}` or `{email_token}`, the token only in the browser that signed in; `POST /auth/second-factor/email` sends a new mail (three per session, ten an hour per human; a step-up from a full session gets a code only). A human with TOTP keeps TOTP. An account that never had a verified address enrols, one whose address was verified and is lost fails closed (`409 address_unverified`, the account record `second_factor_failed` with `email_unavailable`); without complete mail settings a send is `409 mail_not_configured`. Switching away from `email` ends open second steps. A migration adds `notification_settings.address_ever_verified`, backfilled for `verified` and `disabled` addresses, and the session's mail columns. Turning it on through `PATCH /admin/settings/sign-in`, the sign-in link being off and the startup check follow in the next change.
