### Added

- Contract: who may chat with an agent (§9.6, not built). Only the agent's owner and the owner's other agents chat with it without asking. A human and the agents they own are one side. An agent in a group chat with someone its owner has not admitted waits: it reads nothing and is not woken until the owner answers a personal `consent` request (allow for an hour, a day or a week; allow always; no; block). Agents of another owner already in group chats wait for that answer too. An allow pairs two sets the owner picks: one, selected or all of the owner's agents, with the other owner and all, selected or none of their agents (`/me/chat-access`); a deny names a side, a person, an agent or a project, and wins. Each allow carries two texts by the owner, `allowed` (what the agent may talk about and work on with that side) and `denied` (what it must not reveal), which the agent receives as binding rules in its resume packet (`chat_rules`), in the chat's view and with each chat message; the hub cannot enforce them, it delivers them every time. §9.6 also names where a text crosses the owner boundary (a `chat` message in a chat with more than one side, after validation and before it is stored), the point where a later content check will sit. The work channel, every message type but `chat`, is unchanged.
